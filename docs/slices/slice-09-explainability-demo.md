# Slice 09 — Explainability and Single-Page Demo

## Module
`evaluate` / `app`

## Goal
Deliver one presentation-ready Streamlit page that demonstrates the complete loan-risk workflow from applicant input to risk decision, explanation, model-development evidence, and final test results.

## Final configuration
- Model: `models/xgboost_tuned.joblib`
- Frozen threshold: **0.58**
- Model selection: controlled XGBoost tuning on the fixed training/validation split.
- Threshold selection: validation-only, maximizing F1.
- Final test evaluation: completed once in Slice 08.
- Test data is never used by the demo for training, tuning, threshold selection, or explanation.

## Explainability
The single page provides two complementary explanations:

1. **Individual prediction explanation**
   - Uses native XGBoost prediction contributions for the submitted applicant.
   - Positive contributions push the model toward repayment difficulty.
   - Negative contributions push the model toward lower risk.
   - Shows the strongest individual contributions as a signed visualization and table.
   - This is a model explanation, not a causal claim.

2. **Overall model signals**
   - Uses the validation-only permutation importance generated by `src/explainability.py`.
   - Shows which features have the strongest effect on validation PR-AUC overall.
   - This complements, but does not replace, the individual explanation.

## Single-page Streamlit demo

Launch:

```powershell
python -m streamlit run app\app.py
```

There are **no separate navigation pages**. The page is intentionally organized as a presentation flow:

### 1. Enter applicant details
The user enters understandable current application information:
- Age
- Employment duration
- Number of children
- Family members
- Annual income
- Loan/credit amount
- Annual repayment/annuity
- Goods/purchase price

A real validation applicant is selected only as the historical credit profile. This preserves the complete multi-table representation without pretending that a new borrower manually supplies bureau, previous-application, installment, POS/CASH, and credit-card history.

External source indicators are **not** user-entered.

### 2. Risk score and decision
The page shows:
- Predicted repayment-difficulty probability.
- LOW RISK / HIGH RISK decision.
- Frozen 0.58 threshold.
- Distance from threshold.
- Accepted tuned XGBoost model.

The submitted values are transformed through the same saved preprocessing pipeline used by the final model.

### 3. What the entered details produce
The page displays derived financial indicators such as:
- Loan / income
- Annuity / income
- Goods price / income
- Loan / goods price
- Annuity / loan
- Income / family member

These are the interpretable engineered features created by Slice 03.

### 4. Why this risk score?
The page displays the strongest local XGBoost contributions for the submitted applicant.

This lets the presenter explain:
- which signals pushed the score upward,
- which signals pushed it downward,
- and that the final score is produced from the complete applicant representation.

### 5. Overall model signals
Validation-only permutation importance is shown to connect the individual prediction to the broader model behavior.

### 6. How the model was trained and evaluated
The same page documents:
- Seven Home Credit source tables.
- Applicant-level historical aggregation.
- Domain feature engineering.
- Leakage-safe preprocessing.
- 60/20/20 stratified train/validation/test split.
- Logistic Regression, Random Forest, and XGBoost comparison.
- Controlled 20-trial XGBoost tuning.
- Validation PR-AUC model selection.
- Validation-only threshold selection.
- Frozen final model and threshold.

It displays:
- Training / validation / test row counts.
- Model feature count.
- Validation model comparison.
- Final test ROC-AUC, PR-AUC, precision, recall, and F1.
- Final confusion matrix.
- Final ROC curve.
- Final precision-recall curve.
- 0.50 versus 0.58 threshold comparison.

## Local verification

```powershell
python src\explainability.py
python -m streamlit run app\app.py
```

Verify:
1. The page starts without traceback.
2. No external-source fields appear in the applicant form.
3. Submit the default applicant details and record the risk score.
4. Change income, loan amount, annuity, goods price, or age substantially and submit again.
5. Confirm the model recalculates the score. Small changes can remain in the same XGBoost decision region; use a materially different scenario for the live demonstration.
6. Confirm the local explanation updates with the new prediction.
7. Confirm derived ratios match the entered values.
8. Confirm training/validation/test methodology and all final metrics render.
9. Confirm ROC/PR figures and confusion matrix render.
10. Confirm no UI action trains, tunes, or evaluates the test set.
